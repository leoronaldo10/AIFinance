# 财务 AI 资讯：编辑与发布

这是面向一般企业财务人员的第一版资讯通道，暂名「财务 AI 资讯」。优先关注国内 AI 与办公产品的具体变化，说明它与表格、对账、分析、报告和流程的关系。本站不提供对话式财务咨询。

## 日常操作

1. 管理员进入 `/admin/editorial`，添加公开原文的标题、链接和供核对的材料。该操作只保存材料，不抓取网页、不调用模型。
2. 打开稿件，核对原文，填写「发生了什么」「财务为什么关注」「使用条件」「可以怎样尝试」「限制与依据」。可用性不明确时保持「待核实」，区分公告、实测与推断。
3. 选择栏目、场景和是否首页精选，填写编辑说明并保存新版本。再次核对后填写审核说明，点击「审核并发布网站」。退回稿件必须修改形成新版本后才能发布。
4. 在 `/admin/editorial-exports` 选择已发布的网站版本，填写本期标题，生成公众号 HTML / Markdown。最多选择 10 条，按勾选顺序排列；首版选稿器显示最近 30 条。
5. 预览并复制排版到公众号后台，人工检查并发布，再记录公众号链接。此版本没有接入微信的自动发布接口。
6. 同一份选稿也可手动发布为网站当天简报。再次发布明确替换当天简报，保留旧版记录；浏览器中的旧版本不能覆盖其他编辑的新版本。

## 版本与撤回

- 自动整理和人工修改都创建新的草稿快照。新草稿不会覆盖网站正在使用的已审核版本。
- 审核绑定具体版本；并发保存或审批旧版本会提示刷新。编辑、审批和撤回有审计记录。
- 公众号出稿保存引用版本及确切 HTML / Markdown，不随模型重新生成而改变。
- 网站资讯更新或撤回后，依赖旧版的网站简报立即停止公开；重新核对并出稿后可以替换当天简报。
- 公众号出稿列表标记过期引用，已发公众号文章须由编辑到微信后台检查、更正或撤回，本站不能远程撤销它。
- 草稿与撤回内容不进入详情、Markdown、OG、RSS、搜索、精选同步和站点地图等公开出口。自动事件聚合与自动日报暂不公开，避免绕过审核。

## 从旧站升级

迁移 `0039` 增加审核与出稿表，并将旧站公开内容转回待审核状态。原稿、分析、回执和历史记录保留；执行迁移后，原有内容需要重新审核才能公开。迁移脚本会补齐旧文章的审核队列，不调用模型。请在部署维护窗口执行，按现有部署文档备份数据库。

迁移 `0040` 增加主题启用状态：旧主题保留记录，按 `industry/topics.json` 激活当前财务场景主题。原有分类 URL 键保持兼容，展示文案已改成财务栏目。

原框架的七类内容、五个评分维度及权重、预算与付费回执保持不变；没有凭感觉修改精选门槛。后续要用真实样本重新校准。

## 当前运行边界

运行环境需要 Node.js 24 和 PostgreSQL 17；是否已安装、可用须在目标环境核实。隔离预览使用独立 Compose、禁止 worker 和运行期外联，见 [部署说明](deploy.md)。开发时关闭 `COLLECT_ENABLED`、`MODEL_CALLS_ENABLED`、`FEISHU_*_ENABLED`、`INDEXNOW_SUBMIT_ENABLED`。环境中的凭据、数据库、浏览器样稿截图和辅助脚本不提交仓库。

`industry/sources.json` 的旧示范源默认关闭；这不会自动关闭已有数据库中启用的信源，升级后需在后台检查。尚未启用真实采集和模型服务，也未把演示材料当作真实新闻发布。模型提示词已支持财务解读，启用前仍需验证输出质量。

正式上线前还需确定品牌、域名与部署目标，核实国内信源入口，配置模型及预算，并由站点所有者确认条款、隐私说明和真实内容样本。部署步骤见 [deploy.md](deploy.md)。

## 验证

```bash
npm run typecheck
npm run test:preview
# 使用独立空库；名称必须以 _test 或 _ci 结尾。
DATABASE_URL=postgres://127.0.0.1:5432/aifinance_ci node scripts/migrate.ts
DATABASE_URL=postgres://127.0.0.1:5432/aifinance_ci MODEL_CALLS_ENABLED=true npm test
npm run build -w @aihot/web
node --test apps/web/tests/*.test.ts
node scripts/smoke.ts --base http://localhost:3000
```

测试的 `MODEL_CALLS_ENABLED=true` 只用于本地 HTTP 模型替身，不开启工作进程的外部模型调用。原引擎测试使用 `NODE_ENV=test` 下的自动发布夹具；`editorial-review.test.ts` 单独开启实际审核策略，验证完整性、公开出口、并发、引用失效、认证与 CSRF。普通运行环境始终要求审核。
